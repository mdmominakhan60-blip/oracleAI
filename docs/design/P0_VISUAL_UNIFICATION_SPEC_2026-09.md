# oracleAI — P0 «Ночной космос»: единый визуальный каркас Mini App

**Статус:** спека для реализации (BUS-712, по CEO-аудиту против Селена/myselena.ru)
**Владелец UX:** UX/UI Designer · **Реализация:** Frontend Engineer
**Дата:** 9 сентября 2026 · **База:** Mini App v108, дизайн-система Astral Midnight

## 1. Проблема и цель

CEO-вердикт (BUS-668, слайды .scratch_bus668_slides): у конкурента один визуальный мир от первого касания до оплаты; у нас функционал сильнее, но оболочка разъезжается. Аудит кода подтверждает три системных разрыва:

1. **Фон:** starfield един, но базовый цвет `#070713` (15-ritual-redesign.css:957) не равен `--color-bg-primary: #0a0920` (00-tokens.css:20); `bg-cosmos-2.jpg` (десктоп ≥601px) грузится **без cache-busting версии**, а preload в index.html указывает `?v=108`, когда CSS в 01-sky-shell.css:11 и 15-ritual-redesign.css:964 всё ещё ссылаются на `?v=107` — при деплое新版 фон у части пользователей останется старым из кэша.
2. **Primary-кнопка:** правильный градиент `linear-gradient(135deg, var(--champagne-300), var(--champagne-500))` размножен вручную в 7+ правилах (btn-primary, send-btn, nav-btn.active, ptab.active, rel-chip.sel, msg.user, agent-avatar); при этом цвет текста на градиенте дрейфует — 6 разных hex (#251d39, #23192f, #281f3b, #271f38, #291f3c) вместо одного `--color-on-accent` (00-tokens.css:36); и 113 вхождений legacy-золота `rgba(230,193,120)` (#E6C178) против 178 champagne `rgba(245,212,139)` (#F5D48B) — **две разные золотые палитры живут одновременно**.
3. **Прогресс онбординга:** сегментный прогресс существует точечно (palm-progress: 3 шага; tarot-card-progress; fb-progress; daily-ritual-progress), но **многошагового онбординга с единым прогрессом нет вообще** — у конкурента сегментный бар на каждом шаге; у нас пользователь заполнения профиля видит только «01 дата / 02 время / 03 город» текстом (12-misc.js:68).

**Цель P0:** три системных правки, после которых миниапп визуально читается как один мир: (а) единственный источник фона с корректным версионированием; (б) один primary-градиент и один on-accent через токены; (в) единый сегментный прогресс-паттерн для всех многошаговых сценариев.

**Вне рамок P0** (переносится в P1/P2 backlog, не реализовывать в этом цикле): живой образ астролога, продающие карточки тарифов с иконками по паттерну «Градус дня», модалка тест-драйва из чата, отзыв в онбординге, микрокопия «кратко vs развёрнуто».

## 2. Сценарий и принципы

> Пользователь проходит любой многошаговый путь (заполнение профиля, гадание, покупка) и в любой момент видит: тот же ночной космос, ту же золотую primary-кнопку, и всегда понимает, сколько шагов осталось.

Принципы:
- **Один фон — один источник.** Никакой экран не переопределяет космический фон собственным непрозрачным фоном; свои фоны — только у полноэкранных оверлеев с затемнением `rgba(7,7,18,.76+)`.
- **Один primary.** Все primary-действия (кнопка, активная вкладка, выбранная_relationship-чипа, bubble пользователя) — один и тот же градиент из токена. Не-graduated различаются только по токенам вторичного (lilac — агенты/аватары, blush — ошибки/уведомления, success — подтверждения).
- **Прогресс — всегда сегменты.** Многошаг = ≥3 шагов: сегментный индикатор вверху шага, те же токены, что у palm-progress; текст «шаг N из M» рядом для скринридеров (aria-label).

### 3.4. Ликвидация legacy-золотой палитры (P0-обвязка, инкрементально)

113 вхождений `rgba(230,193,120)` — это старое золото #E6C178, не токен. Замена по механике «одно правило = один PR-ханк»: `rgba(230,193,120,.X)` → `rgba(245,212,139,.X)` (или соответствующий champagne-токен, где X сохраняется). Проверять контраст заново только там, где rgba участвует в цвете текста (в фоне/бордере замена безопасна: оба оттенка близки по светлоте, L≈76% vs 80%).

Порядок замены по модулям (по убыванию вхождений): 15-ritual-redesign → 09-chart-panels → 03-profile → 13-toolbar-sheet → 12-compat → 11-misc → 14-widgets → 08-day-memory → 21-chat-stage → 07-home-bg → 10-tarot-carousel → 06-composer-chat → 04-atmosphere → 02-skeleton → 01-sky-shell → 00-tokens (sh-gold).

**Критерий приёмки:** `grep -c 'rgba(230,193,120' miniapp/css/*.css` суммарно ≤ 10 (остаток — только сознательные исключения, перечисленные в комментарии в 00-tokens.css).

### 3.5. Управление версиями ассетов (устранение класса багов)

Баг «preload v=108 vs CSS v=107» — системный: версии раскиданы по 3+ файлам при каждом деплое. Требование: версия ассета выносится в CSS-переменную на :root:

```css
:root { --asset-v: v108; }
```

…и все url() используют `url("/static/img/bg-cosmos.jpg?var(--asset-v)")`. **Внимание:** CSS-переменные НЕ работают внутри url() — это ограничение платформы. Поэтому рабочий вариант для Frontend: генерация версий при сборке (esbuild-replace) либо синхронизация grep-скриптом в CI (`scripts/check-asset-versions.sh` — падает, если ?v= расходится между index.html и css/*). Frontend выбирает механику; UX-требование одно — расхождение версий невозможно by construction.

## 5. Доступность (WCAG)

- **Контраст on-accent на градиенте:** #251d39 на #ffe9b4 → 8.7:1, на #eabf68 → 7.1:1 — AA/AAA проходит на обоих стопах градиента. Единый on-accent гарантирует, что дрейф hex не уводит контраст ниже 7:1.
- **Прогресс-бары:** aria-label обязателен («Шаг 2 из 3: качество фото»), визуальные сегменты aria-hidden (паттерн уже применён в 06-home.js:71 — daily-ritual-progress).
- **Фокус:** primary-кнопки уже наследуют `--focus-ring` (00-tokens.css:37) — при переходе на var(--grad-primary) фокус-стили не трогать.

## 7. Риски и альтернативы

- **Риск:** замена 113 rgba по каскаду может вскрыть скрытые зависимости (места, где legacy-золото специально тусклее). Митигация: инкрементальная замена по модулям + визуальный smoke после каждого модуля (скрипты bus399-shot-*.png уже существуют как паттерн).
- **Альтернатива «не трогать legacy»:** отклонена — две живые золотые палитры означают, что любой новый экран тянет случайную из них; это источник будущих расхождений.
- **Альтернатива «новый онбординг-флоу с нуля»:** отклонена для P0 — CEO-запрос был про целостность оболочки, не про новый сценарий; полноценный онбординг — отдельная задача после P0/P1.
