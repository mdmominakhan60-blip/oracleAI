# oracleAI — «Сегодня в фокусе»: UX-редизайн главной Mini App

**Статус:** спека для реализации (BUS-512, finding R-10 из P2-002 accessibility device run)
**Владелец UX:** UX/UI Designer · **Реализация:** Frontend Engineer
**Дата:** 8 сентября 2026 · **База:** Mini App v76+, дизайн-система Astral Midnight

## 1. Проблема и цель

Голос оператора: «не нравится главная — слишком много мусора и кнопок, пользователь будет путаться; оставить главное — пользователь быстро открывает телефон, чтобы посмотреть гороскоп».

Сегодня `renderHome()` (`miniapp/js/06-home.js`) отдаёт **7 секций в общем потоке**: welcome-карточка, ежедневный ритуал (0/2), луна-сегодня + лунная неделя, персональный прогноз, карта дня, next_action, док-сетка 4 агентов. Это ~15+ интерактивных элементов на одном экране; ни одна секция не гарантирует сценарий «открыл → увидел главное за 3 секунды» (finding R-10, major).

**Цель:** первый экран отвечает на вопрос дня и даёт один явный путь «спросить»; всё остальное — скрыто до явного интереса; любая из 5 текущих функций — ≤2 тапов.

## 2. Priority-сценарий дня

> **«Открыл → за 3 секунды увидел главное»**: дата, гороскоп на день, фаза Луны — прямо в первом экране; одна главная кнопка «Спросить о своём дне» ведёт в чат с Лилит.

Вторичные сценарии (не на первом экране, но ≤2 тапов): отмечу ритуал/дневник, посмотрю лунную неделю, переверну карту дня, выберу проводника.

Контракт данных не меняется: `GET /api/today` (forecast, card, moon, next_action) + `GET /api/moon/week` + pulse (diary/prompt/practices) — всё уже есть, редизайн чисто интерфейсный.

## 3. Информационная архитектура главной

| Блок | Содержание | Источник данных | Действие | Состояние по умолчанию |
| --- | --- | --- | --- | --- |
| **Hero «Сегодня»** | дата; лунный чип (фаза + лунный день); гороскоп (3 строки + «Развернуть»); CTA «Спросить о своём дне»; вторичная ссылка next_action | `t.moon`, `t.forecast`, `t.next_action` | CTA → чат oracle; next → chat-fn | **открыт** (весь первый экран) |
| Аккордеон «Мой ритуал» | счётчик 0/2 в заголовке; внутри — шаги дневника и практики | pulse | шаги → chat-fn / p-action | свёрнут |
| Аккордеон «Карта дня» | имя карты + номер в заголовке; внутри — flip-карта со значением | `t.card` | flip; подсказка к чату | свёрнут |
| Аккордеон «Луна на неделе» | текущая фаза в заголовке; внутри — moon-today + 7 строк недели + новолуние/полнолуние | `moonWeek`, `t.moon` | раскрытие строк | свёрнут |

**Убирается с главной:** док-сетка агентов (полный дубль уже живёт в хабе «Чаты»), декоративная prompt-строка, поэтичный H1 + абзац welcomeCopy (короткое приветствие с именем остаётся одной строкой). Навигация не меняется: те же 4 таба.

Обоснование против альтернатив (см. §12): ежедневный контент (ритуал, луна, карта) остаётся в daily-контексте главной, но сворачивается; постоянные сущности (проводники) живут в хабе; отдельный экран «Сегодня подробнее» отвергнут — лишний шаг между пользователем и ритуалом.

## 4. Hero «Сегодня» — контракт

Каркас — существующая `welcome-card` (CSS `16-visual-qa.css`), расширенная двумя элементами.

```
┌──────────────────────────────────────────┐
│ ✦ СЕГОДНЯ — БЕЗ СПЕШКИ      8 сентября, пн│  ← welcome-card__top (kicker + fmtDate, как сейчас)
│                                          │
│ Рада видеть тебя, Аня                    │  ← приветствие, 1 строка (существующая gendered-логика)
│                                          │
│ [🌙] Растущая Луна · 14-й лунный день     │  ← НОВОЕ: лунный чип (t.moon)
│                                          │
│ ЗНАК НА СЕГОДНЯ                           │  ← section-kicker (todaySign)
│ Текст прогноза до 3 строк, обрезается     │  ← t.forecast, line-clamp:3
│ клампом…                      [Развернуть]│  ← кнопка снимает кламп (aria-expanded)
│                                          │
│ [ Спросить о своём дне              → ]   │  ← ritual-cta → chat oracle (единый CTA)
│  next: Построить натальную карту        ›│  ← t.next_action одной ghost-строкой (chat-fn)
└──────────────────────────────────────────┘
```

Правила:

- **Один primary CTA** на весь экран — «Спросить о своём дне» (`ritual-cta`, актёр `data-act="chat" data-chat="oracle"`). Существующий `ritualCta` («Открыть разговор») заменяется на новый ключ `focusAskToday` (§11).
- **Лунный чип**: SVG-фаза (`moonSvg(t.moon.emoji)`) + `t.moon.name` + `homeFormat('lunarDay', { day })`. Без совета (`t.moon.advice`) — совет уезжает в аккордеон «Луна на неделе», чип только констатирует контекст дня.
- **Прогноз**: `t.forecast` в 3 строки (`-webkit-line-clamp: 3`), кнопка «Развернуть» снимает кламп и разворачивает до полного текста на месте (без навигации). При `t = null` — существующий `forecast-fallback`.
- **next_action**: одна ghost-строка `next: [t.next_action.title] ›` (`btn-ghost`, приглушённый, под CTA). Тап → `chat-fn` с готовым `chat`/`fn`/`cta`. Вариант без `fn` (только текст) — строка не рендерится.
- **Сезонный эксперимент** `home_ritual_entry` (control/seasonal): seasonal-вариант = одна строка-подпись `seasonal.title` под приветствием (без блока с абзацем copy — компактный вариант прежнего блока). `trackExperiment` не меняется.

## 5. Аккордеон-секции

Новый универсальный компонент `.home-acc` (заголовок-кнопка + скрытое тело), паттерн раскрытия — как существующие строки `mc-day`.

```
┌──────────────────────────────────────────┐
│ ◌  Мой мягкий ритуал          0/2       ▾ │  ← кнопка-заголовок, min-height 44px
├──────────────────────────────────────────┤
│ 🎴  Карта, которая рядом       XIV      ▾ │
├──────────────────────────────────────────┤
│ 🌖  Лунный календарь   Растущая    ▾     │
└──────────────────────────────────────────┘
```

- **Заголовок** = `<button class="home-acc-head" aria-expanded="false" aria-controls="...">`: иконка (✦/карта-мини/SVG-фаза), название, контекстный бейдж (0/2 · имя карты+номер · фаза дня), шеврон ▾.
- **Тело** = `<div id="..." hidden>`: раскрывается по тапу, `--motion-quick`, при `prefers-reduced-motion` — мгновенно.

Содержимое тел — существующие компоненты без переделки:

1. **«Мой ритуал»** → вся текущая секция `daily-ritual` (progress-полоса, статус-строка, сетка шагов дневник/практика, заметка). Бейдж = `ritualCompleted`/2; при 2/2 тон заголовка «завершено» (существующий `ritualTone` остаётся внутри).
2. **«Карта дня»** → `card-day-big` с flip-картой, `cd-name`, `cd-note`, `cd-hint`. Бейдж = `t.card.name` + `toRoman(t.card.num)`; мини-превью 32px (`t.card.img`).
3. **«Луна на неделе»** → `moon-today` + строки `mc-day` + новолуние/полнолуние-заметка. Бейдж = текущая фаза + лунный день.

## 8. Состояния и ошибки

| Состояние | Поведение |
| --- | --- |
| Загрузка `/api/today` | hero рендерится сразу: статичная строка даты + приветствие; прогноз — 3 shimmer-строки; чип луны — из `moonWeek[0]` если уже есть, иначе скрыт; CTA активен (чат не зависит от today) |
| `t = null` (ошибка API) | прогноз → существующий `forecast-fallback`; аккордеоны «Карта»/«Луна» не рендерятся (текущие условные блоки); «Мой ритуал» живёт на pulse-данных как сейчас |
| `t.card = null` | аккордеон «Карта дня» не рендерится |
| `moonWeek` пуст | аккордеон «Луна» не рендерится; чип в hero — из `t.moon` либо скрыт |
| Ритуал 2/2 | бейдж заголовка ✓✓, тон «завершено», шаги остаются доступными |
| Нет имени пользователя | приветствие — существующая neuter-форма `gendered()` |
| `next_action` без `fn` | ghost-строка не рендерится |

## 9. Доступность (стандарт, не опция)

- **Контраст**: прогноз `--color-text-primary` на `--color-bg-primary`; чип и ghost-ссылка — `--color-text-secondary`/`--color-text-muted` на базовом фоне; всё ≥ 4.5:1 (AA), проверка `npm run test:axe`.
- **Тач-таргеты**: все заголовки аккордеонов, CTA, шаги, ghost-ссылка ≥ `--touch-target` (44px).
- **Клавиатура**: аккордеоны — нативные `<button aria-expanded aria-controls>`; flip-карта переводится с `div[data-act]` на `<button>` с `aria-label` («Перевернуть карту») — сейчас она недоступна с клавиатуры (синхронно с задачами R-8/R-9, BUS-509/510); «Развернуть» прогноз — `aria-expanded`.
- **Reduced motion**: раскрытие аккордеонов и flip без анимации (`prefers-reduced-motion`), переходы из `--motion-*` только при отсутствии ограничения.
- **Фокус**: видимый `--focus-ring` на каждом интерактивном элементе; порядок таба: CTA → next → заголовки аккордеонов.

## 10. Эксперимент `home_ritual_entry`

Механика не меняется (`experimentVariant` + `trackExperiment`, `miniapp/js/01-utils.js:437`): control — hero без сезонной строки, seasonal — со строкой `seasonal.title` под приветствием. После релиза — пересмотреть метрику эксперимента (вход в ритуал) вместе с Experiment Manager: hero стал компактнее, точка входа сместилась в аккордеон.

## 12. Отклонённые альтернативы

| Альтернатива | Почему нет |
| --- | --- |
| Второй экран «Сегодня подробнее» для ритуала/луны/карты | Лишний шаг между пользователем и ежедневным действием; навигационная нагрузка вместо одного скролла |
| Аккордеоны открыты по умолчанию | Возвращает проблему «мусора» на первом экране |
| Перенос ритуала в «Профиль» | Ежедневное действие должно жить в daily-контексте «сегодня», профиль — постоянные данные |
| Полный отказ от next_action | Это главный мост к функциям (карта/совместимость/расклад) и engagement-петля; даунгрейд до одной строки сохраняет пользу без шума |
| Карта дня в hero вместо прогноза | Операторский сценарий — «быстро посмотреть гороскоп»; прогноз первичен, карта — визуальное любопытство второго уровня |

## 13. Критерии приёмки для Frontend

1. Первый экран (375×667, iPhone SE): hero виден целиком, заголовки аккордеонов не выше нижней кромки — «главное за 3 секунды» без скролла.
2. Матрица §6 — все функции ≤2 тапов, подтверждено e2e.
3. Ни одного нового токена; `check_design_contract` зелёный.
4. `test:axe` зелёный: контраст AA, таргеты 44px, аккордеоны и flip с клавиатуры, focus-ring.
5. RU/EN синхронны; устаревшие ключи HOME_I18N вычищены.
6. e2e: раскрытие всех 3 аккордеонов, «Развернуть» прогноза, CTA → чат oracle, ghost next → chat-fn, flip карты, эксперимент-хеш на месте.
7. Контракт API не тронут (только `miniapp/`): `GET /api/today`, `moon/week`, pulse — без изменений.

Спека — единственный источник макета; расхождения с реализацией фиксируются в PR-ревью против этого документа.
