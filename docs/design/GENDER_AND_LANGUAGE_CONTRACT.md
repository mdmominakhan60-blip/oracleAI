# Контракт пола и языка профиля

## Цель

OracleAI должна обращаться к пользователю корректно на русском и английском. Новый профильный атрибут `gender` служит только для языковой формы обращения и инструкций модели; он не используется для интерпретаций, рекомендаций, тарификации или сегментации.

## Данные и совместимость

| Поле | Допустимые значения | Значение по умолчанию | Назначение |
|---|---|---|---|
| `users.gender` | `f`, `m`, `NULL` | `NULL` | Выбранная пользователем форма обращения |
| `users.lang` | `ru`, `en` | `ru` | Язык интерфейсных и агентных текстов |

`NULL` — корректное состояние для существующих профилей и для пользователя, который ещё не сделал выбор. В этом случае интерфейс и системная инструкция используют нейтральные формулировки. Миграция добавляет колонку без изменения существующих записей.

## Онбординг

1. После имени пользователь выбирает «Женский» или «Мужской»; кнопки и пояснение выводятся на текущем языке профиля.
2. Выбор сохраняется сразу, затем запускается существующая последовательность даты, времени и города рождения. Пользователь может нажать «Пропустить» и продолжить без указанного пола.
3. Если Telegram передаёт поддерживаемый язык `ru` или `en` для нового аккаунта, он применяется при создании профиля. Выбор языка в Mini App остаётся приоритетной ручной настройкой.
4. У уже завершивших онбординг пользователей поток не перезапускается: пол можно указать, очистить или изменить в разделе профиля Mini App.

## Лингвистические правила

| Язык | Женщина | Мужчина | Не указан |
|---|---|---|---|
| Русский | женский род, например «ты готова» | мужской род, например «ты готов» | нейтральная форма, например «можно начать» |
| English | стандартное `you` без рода; допускаются нейтральные обращения | стандартное `you` без рода; допускаются нейтральные обращения | стандартное `you` без рода; допускаются нейтральные обращения |

LLM получает только краткую, недвусмысленную языковую инструкцию: отвечать на языке профиля, а для русского использовать выбранный грамматический род или нейтральный язык при `NULL`. Английские ответы не получают искусственно гендерные местоимения.

## API и валидация

`GET /api/me` возвращает `gender`. `POST /api/profile` принимает только `f`, `m` или `null`; другие значения отклоняются с ошибкой 422. Метод `PATCH` поддерживает тот же контракт как семантический alias. Клиент никогда не отправляет отображаемые подписи (`«Женщина»`, `«Male»`) вместо кодов.

## Проверки

Регрессии покрывают миграцию, разрешённое обновление профиля, русский и английский онбординг, формирование LLM-контекста, а также сохранение нейтрального fallback для старых профилей.
