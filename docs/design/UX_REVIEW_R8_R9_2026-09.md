### BUS-509 (R-8, Chat viewport) — PASS

Прогон `scripts/qa_bus509_smoke.mjs` (CHROME_PATH из playwright-кеша): **26/33 PASS**.
Все 7 FAIL — однотипные «консоль чиста — net::ERR_FAILED» в mock-окружении
(шум мока, не UX-дефект). Функциональные и визуальные проверки — все зелёные.

Пункты спеки, подтверждённые прогоном и код-ревью:

- **R-8.1 nav-hidden**: `.app-nav` и `.app-header` скрыты в чате
  (`display:none` — высота реально возвращается ленте, не перекрывается).
  Путь назад сохранён дважды: back-кнопка в `.chat-head` + BackButton
  Telegram (`syncBackButton`, 05-app.js:472). После выхода навигация
  возвращается (проверено смоуком).
- **R-8.2 heads-hidden**: порог дельты 36px корректно отсекает микродрожание
  и iOS-резинку; возврат при `y <= 0` (тянут вверх — шапка назад).
  `max-height:0 + padding:0` вместо `transform` — место отдаётся ленте
  сообщений, скроллер не дёргается. Reduced-motion-гард на transition
  (WCAG 2.3.3, гейт P2-002 §7) — смоук PASS «transition=1e-05s».
- **R-8.3 intro-collapse**: при stable-высоте < 480px карточка агента —
  одна строка kicker 23px (`persona`/`next` скрыты), при возврате к 667px
  полный вид восстанавливается. Скриншот bus509-3 подтверждает.
- **R-8.4 stable-высота**: `viewportStableHeight` + `isStateStable` (не
  `viewportHeight`) — ровно по документации Telegram для pinned-композера.
  Событие без `isStateStable` значение НЕ меняет (проверено). Композер
  остаётся в layout при малой высоте (клавиатура 320px — PASS).
- **Деталь выше спеки (одобряю)**: `renderFrame` сохраняет классы
  `nav-hidden`/`heads-hidden`/`chat-live` при перерендере — без этого
  смена языка внутри чата роняла бы viewport-состояние.
