# BUS-1615 (DevOps): .env восстановлен + compose-vs-env канон — 2026-10-11

## Outcome
Обе accept-цели задачи выполнены и перепроверены live. `.env` на момент рана уже
существовал (создан 2026-10-10 16:15, до рана), `CUSTOM_LLM_BASE_URL` уже был
исправлен — поэтому чаша весов сместилась: реальным дефектом оказался не пустой
`.env`, а то, что `docker compose` вообще не мог его увидеть из `infra/`.
Починено и сделано воспроизводимым.

## Findings
1. `.env` в корне репо есть, 76 ключей, заполнен частично. Причины
   `required variable ... is missing` не было — compose просто не читал файл.
2. Корневая причина: `docker compose` авто-ищет `.env` в своём project directory
   (`infra/`), а `infra/docker-compose.yml:20` объявляет `env_file: ../.env`.
   Любая команда `cd infra && docker compose ... config -q` падала на 17
   интерполяциях. Стек был живым только благодаря явному `--env-file` в
   `infra/prod-stack-up.sh:92` (ранее L92, сдвинуто ensure-блоком) и в
   `.github/workflows/deploy.yml:86`.
3. `infra/.env` → symlink `../.env` закрывает канон. Создаётся идемпотентно в
   `infra/prod-stack-up.sh`, оба пути в `.gitignore:1` (секреты не в git).
4. `docker compose --project-directory ..` НЕ помогает — Compose v5.6.0 ищет
   `.env` строго внутри project dir; проверено, ошибка та же.
5. Контейнеры НЕ пересоздавались: все возрастом с 2026-10-09/10, redeploy не
   запускался — ограничение задачи соблюдено.
6. Побочные дефекты вне scope (НЕ правил, вынесены отдельно):
   - `infra-bot-1`: 95 рестартов, `TelegramUnauthorizedError` — `BOT_TOKEN`
     placeholder (len=13). Это board-гейт BUS-1564, в задаче явно исключён.
   - `infra-alertmanager-1`: crash-loop, 25 рестартов. Пустой `ALERT_CHAT_ID`
     валит fail-closed гард `infra/observability/alertmanager-entrypoint.sh:10`
     (BUS-855). Значение — данные владельца; гард ослаблять нельзя.
   - `ALERT_BOT_TOKEN` в `.env` отсутствует вовсе, entrypoint:33 фолбэчит на
     `BOT_TOKEN`, т.е. и с заполненным `ALERT_CHAT_ID` алерты молчали бы.
7. `.env` содержит данные только dev-окружения (`APP_ENV=dev`,
   `WEBAPP_URL=https://localhost:8443`, `DOMAIN=localhost`, `PUBLIC_URL` пуст).
   Прод-VPS это не делает готовым — там свой `.env` с `APP_ENV=production` и
   `PROD_CANONICAL_HOST` (в локальном `.env` такой ключ отсутствует, и это
   корректно: `prod-stack-up.sh` должен отказать локальному подъёму прода).

- `python3 -B scripts/check_compose_overrides.py` → все 6 гейтов PASS, `.env` затронут и восстановлен корректно.
- GitNexus `detect-changes --scope all` → `risk_level: low`, `affected_count: 0`.
- Слепок env (len + sha256[:8], без значений): `docs/RELEASE/reports/2026-10-11-bus1615-env-fingerprint.txt` (78 строк).
- Коммит в `dev`: `416a9d4` (только 2 файла — `infra/prod-stack-up.sh`, `docs/DEPLOYMENT.md`).

## Problems
- `BOT_TOKEN` placeholder → бот в crash-loop (board-гейт, владелец — board).
- `ALERT_CHAT_ID`/`ADMIN_ID`/`PAYMENT_ALERT_CHAT_ID` пусты → alertmanager мёртв
  (данные владельца). Плюс отсутствующий `ALERT_BOT_TOKEN`.
- Пустые ключи, не блокирующие стек: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`,
  `DEV_KEY`, `PUBLIC_URL`, `ORACLEAI_PALM_LINE_MODEL`,
  `ORACLEAI_MEDIAPIPE_MODEL`, `HOROSCOPE_CHANNELS`, `PADDLE_*` (3 шт).
- Локальный `.env` = dev-профиль; прод-VPS требует отдельного заполнения.

## Recommendations
1. Board: заполнить `BOT_TOKEN` (BUS-1564) и `ALERT_CHAT_ID` +
   `ALERT_BOT_TOKEN` — после этого alertmanager выйдет из crash-loop без правок
   кода, достаточно `up -d alertmanager`.
2. Держать канон: `.env` только в корне, `infra/.env` — симлинк. Ручные
   compose-команды из `infra/` теперь работают, но решения уровня prod
   (`APP_ENV=production`) по-прежнему идут через `prod-stack-up.sh` / DEPLOYMENT.md.
3. Проверить `docs/RELEASE/reports/2026-10-11-bus1615-env-fingerprint.txt` при
   следующем аудите — он показывает, какие ключи остались пустыми.
