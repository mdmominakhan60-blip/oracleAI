# OracleAI — Device Accessibility Runbook (инструкция оператора, гейт P2-002)

**Кому:** оператор с реальными iPhone и Android-телефоном (Telegram установлен). Опыт доступности не требуется — все жесты описаны внутри.
**Что проверяем:** Mini App oracleAI в Telegram WebView на реальных устройствах. Чек-лист сценариев: `ACCESSIBILITY_CHECKLIST.md` (разделы 1–8, ID K-1..K-8, V-1..V-12, T-1..T-5, C-1..C-3, TT-1..TT-4, SA-1..SA-5, RM-1..RM-4, D-1..D-5).
**Время:** ~60–90 минут на устройство (можно в два захода).
**Результат:** заполненный протокол + скриншоты/записи экрана для каждого FAIL.

## 0. Что нужно до старта

| # | Предусловие | Как проверить |
|---|---|---|
| 0-1 | iPhone с notch/Dynamic Island, актуальные iOS и Telegram | Настройки → Основные → Об этом устройстве |
| 0-2 | Android-телефон с жестовой навигацией, актуальные Android и Telegram | Настройки → О телефоне |
| 0-3 | Доступ к staging Mini App | Открыть Telegram → найти **@oracleai_staging_bot** → `/start` → кнопка меню «✨ Оракул» открывает Mini App. Если не открывается — сверить URL кнопки с `infra/staging/PUBLIC_URL.txt` (quick-tunnel меняется при рестарте, DevOps обновляет автоматически); URL не совпал — остановиться и сообщить координатору |
| 0-4 | (Опционально) Bluetooth-клавиатура | Для раздела 1; если клавиатуры нет — раздел 1 пометить N/A, его частично покрывают разделы 2–3 |
| 0-5 | Возможность делать скриншоты/запись экрана | iOS: боковая+громкость; Android: питание+громкость вниз |

Не проверять по этому чек-листу: контраст по токенам (`00-tokens.css`) — уже замерен statically и автоматически (axe: 0 violations); экраны, недоступные без Telegram-контекста, недоступные в staging (реальная оплата — только UI-оболочка).

## 1. Подготовка устройств (по одному разу на каждом)

**iPhone (после каждой перенастройки — перезапустить Telegram):**
- Тёмная системная тема: Настройки → Экран и яркость → Тёмное.
- Язык RU: Настройки → Основные → Язык и регион. EN-часть проверяется внутри приложения (профиль → язык).
- VoiceOver: Настройки → Универсальный доступ → VoiceOver → вкл. Тройное нажатие боковой кнопки — быстрое вкл/выкл (Настройки → Универсальный доступ → Быстрая команда).
- Reduced Motion (позже, раздел 7): Настройки → Универсальный доступ → Движение → Уменьшить движение.
- Dynamic Type max (раздел 8): Настройки → Универсальный доступ → Экран и размер текста → Крупный текст → макс.

**Android:**
- Тёмная тема: Настройки → Экран → Тёмная тема.
- TalkBack: Настройки → Спец. возможности → TalkBack → вкл. Выключение: зажать обе кнопки громкости.
- Reduced Motion (раздел 7): Android 12+: Настройки → Спец. возможности → Удалить анимации. Иначе: Для разработчиков → отключить все три «Анимация: масштаб».
- Font scale 1.3x (раздел 8): Настройки → Экран → Размер и стиль экрана → Размер шрифта ближе к максимуму.

**Порядок прогона на каждом устройстве:** разделы 2–8 в обычном режиме (тема RU, тёмная, стандартные шрифты, анимации вкл.) → включить Reduced Motion → раздел 7 → вернуть анимации → включить крупный шрифт → раздел 8 → вернуть. Раздел 4 (контраст) — под конец, у окна при дневном свете, яркость ~50%.

## 2. Жесты — справочник оператора

**iOS VoiceOver:** свайп вправо/влево одним пальцем — следующий/предыдущий элемент; двойной тап — активировать (в любом месте экрана); **Z-жест**: двумя пальцами свайп назад-вперёд (буква Z) — назад/закрыть; тремя пальцами свайп — прокрутка; двумя пальцами свайп вниз — читать всё с текущего места; двумя пальцами поворот по кругу — ротор (выбор режима навигации).

**Android TalkBack:** свайп вправо/влево — следующий/предыдущий; двойной тап — активировать; **назад**: одним пальцем свайп вниз-затем-влево одним движением; прокрутка: тремя пальцами свайп вверх/вниз; меню TalkBack: вниз-затем-вправо одним движением.

**Правило фиксации FAIL:** скриншот/запись экрана немедленно, ID сценария в имя файла (`<ID>_<устройство>.png`, напр. `V-7_ios.png`).

## 3. Прогон по разделам (что именно делать)

Ниже — действия; ожидания перечислены в чек-листе (ссылки на ID). Результат каждой ячейки: `OK` / `FAIL: <описание + major/minor>` / `N/A: <почему>`.

### Раздел 1 — клавиатура (если есть BT-клавиатура; иначе N/A)
На iPhone/Android подключить клавиатуру, открыть Mini App, идти Tab'ом: онбординг → home → чат → профиль → карта → Таро. Проверить K-1..K-8: порядок фокуса = визуальному, фокус-рининг виден, Esc в sheet закрывает, Enter в чате отправляет, Shift+Enter — перенос строки. K-7: фокусируются ли карты Таро, активация Enter.

### Раздел 2 — VoiceOver (iPhone)
Включить VoiceOver, перезапустить Telegram, открыть Mini App.
- V-1: с самого верха онбординга свайпами вправо — не озвучивается ли звёздный фон (декор должен молчать).
- V-2: пройти онбординг до конца (Skip должен быть достижим сразу).
- V-3: home — кнопки должны звучать «<имя>, кнопка».
- V-4/V-5: написать в чат — новое сообщение озвучивается само; статус «печатает/загружаем» объявляется.
- V-6: вызвать ошибку (отправить в чат при недоступном API не выйдет на staging — тогда пропустить; любой toast, если появится, объявляется).
- V-7: открыть tools sheet (чипы инструментов над чатом) — фокус внутрь; Z-жест закрывает; после закрытия VoiceOver на кнопке-триггере.
- V-8: форма совместимости (профиль → совместимость): метки полей и подсказка даты озвучиваются.
- V-9: экран карты: статусы загрузки объявляются; SVG-декор молчит.
- V-10: Таро: тянуть карту — статус расклада озвучивается на всех стадиях.
- V-11: тарифы/платежи: кнопка оплаты с именем; ошибки читаются (реальную оплату не проводить — только UI до подтверждения).
- V-12: жесты прокрутки не «застревают» на невидимых элементах.

### Раздел 3 — TalkBack (Android)
Включить TalkBack, перезапустить Telegram, открыть Mini App. T-1..T-5 — те же маршруты, что и V-1..V-10: онбординг, чат (история/статусы), sheets (фокус внутрь, «назад» жестом закрывает), двойной тап по чипам инструментов и доку активирует с первого раза, Таро перелистывается TalkBack'ом.

### Раздел 4 — контраст (дневной свет, яркость ~50%)
- C-1: у окна при свете дня просмотреть все экраны RU и EN — весь текст читаем? Особое внимание: muted/subtle текст (второстепенные подписи, хинты).
- C-2: найти disabled-состояния (неактивные кнопки/чипы, статусы платежей) — различимы?
- C-3: экраны с градиентным космос-фоном (home, Таро) — текст поверх градиента читаем?
Если сомнение — скриншот + пометка «проверить пипеткой» (дальше разберу я).

### Раздел 5 — touch targets (обычный режим)
- TT-1: пройтись пальцем по нижней навигации, чипам инструментов, кнопкам чата — попадания уверенные? Соседние элементы не активируются случайно?
- TT-2: мелкие иконки: удаление записи памяти (профиль → память), закрытие sheets, «✕» модалок — промахи?
- TT-3: карусель Таро и выбор связи в compat — переключение без соседних активаций.
- TT-4: поля даты/времени/города в форме compat — нативный пикер Telegram открывается с первого тапа.
Критерий: 5 повторных тапов на каждый элемент — ни одного промаха. Промах → FAIL + скриншот.

### Раздел 6 — safe-area
- SA-1 (iPhone): контент не заходит под «уши»/Dynamic Island; хедер читаем.
- SA-2: нижняя навигация и composer чата не перекрыты home-индикатором.
- SA-3 (iPhone): ландшафт — чат-композер, нижняя навигация, открытый sheet не перекрыты/не обрезаны.
- SA-4 (Android): жестовая навигация — нижние панели не перекрыты полоской.
- SA-5: открыть клавиатуру в чате — composer выше клавиатуры, поле ввода видно.

### Раздел 7 — reduced motion (при включённой настройке)
- RM-1: онбординг, home, чат, Таро — метеоры/мерцание/орбиты/параксис не анимируются (или минимум).
- RM-2: отправка сообщения, открытие/закрытие sheet, вытягивание карты — без крупных смещений.
- RM-3: результат compat/расклада появляется без плавного скролла.
- RM-4: всё функционально достижимо.

### Раздел 8 — динамический текст и прочее
- D-1: max шрифт — чат, профиль, тарифы: текст растёт, ничего не обрезано до нечитаемого.
- D-2: если в WebView доступен zoom — 200% без двойного скролла (если нет — N/A).
- D-3: сменить язык в профиле RU→EN→RU — надписи и озвучивание SR меняются.
- D-4: (информационно, если есть возможность посмотреть) язык документа меняется — основной признак виден в D-3.
- D-5 (стресс, iPhone): ландшафт + открытая клавиатура + VoiceOver — нет зависаний фокуса.

## 4. Протокол (как сдать результаты)

Формат — обычный текст/маркдаун, по одному блоку на устройство:

```
Устройство: iPhone 14, iOS <версия>, Telegram <версия>
Дата: <дата>
Раздел 1 (клавиатура): N/A (нет клавиатуры)
K-1: OK
...
V-1: OK
V-4: FAIL major — новые сообщения чата не озвучиваются VoiceOver автоматически
  Скриншот: V-4_ios.png
...
```

Для каждого FAIL: ID, severity (blocker = флоу невозможен / major = сильно мешает / minor = косметика), описание, скриншот/запись. Скриншоты передать вместе с протоколом координатору (собирающему этот документ) — они будут приложены к issue BUS-112, а blocker/major станут задачами Frontend Engineer.

После прогона на двух устройствах: вернуть координатору 2 протокола + архив скриншотов. Всё — чек-лист, ожидания по каждому ID — в `docs/RELEASE/ACCESSIBILITY_CHECKLIST.md`.
