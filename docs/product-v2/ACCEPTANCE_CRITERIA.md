# OracleAI v2 — Acceptance Criteria

Проверяемые условия. Каждый критерий имеет: что проверяем, как, и какое свидетельство считается доказательством.

**Правило доказательства:** критерий считается выполненным только при наличии выходных данных конкретной команды или теста. Утверждение «работает» без вывода команды не принимается.

---

## 0. Общие инварианты (проверяются на каждом этапе)

| ID | Критерий | Как проверить | Свидетельство |
|---|---|---|---|
| INV-1 | Старый `miniapp/` не изменён | `git diff --stat HEAD -- miniapp/` | Пусто (кроме Этапа 3, где меняется `index.html`) |

## 1. Этап 1 — Фундамент `frontend-v2/`

**Границы этапа 1 (уточнение, снимает конфликт с планом миграции).** На первом этапе backend не трогается, API не подключается, авторизация не создаётся. Поэтому критерии A1-5 и A1-6 относятся к **типизированной заготовке**, а не к работающему клиенту: реальный API-слой включается на Этапе 2 (`MIGRATION_PLAN.md`). Preview-данные допустимы только там, где экран помечен как placeholder, и обязаны быть явно обозначены в UI.

| ID | Критерий | Проверка |
|---|---|---|
| A1-1 | Vite+React+TS собирается | `cd frontend-v2 && npm run build` |
| A1-2 | Типы чистые | `npx tsc --noEmit` |
| A1-3 | Токены совпадают с R03 §2.1 | Сверка значений `--color-*` с таблицей в `DESIGN_SYSTEM.md` §2 (15 значений). Производные (`--focus-ring`, `--hover-bg`, `--grad-primary`) проверяются отдельно: они заданы **один раз** в токен-файле и не дублируются в компонентах |
| A1-4 | Нет новых hex вне токенов | Grep по `frontend-v2/src` на `#[0-9a-fA-F]{6}` вне файла токенов → 0. Исключение: `rgba()` внутри `--focus-ring`/`--hover-bg` в самом токен-файле |
| A1-5 | Типизированная заготовка API-слоя | Есть модуль `src/api/` с типизированными сигнатурами `mintSession`, `authHeaders`, `friendlyError` и стратегией ретраев (5xx только GET), **без сетевых вызовов**: методы помечены как не подключённые. Реальные вызовы и юнит-тесты на 401-реминт — Этап 2 |
| A1-6 | i18n — единый слой | Все строки UI через словарь; 0 тернарников `lang === 'en'` |
| A1-7 | Старый интерфейс работает | `git status` — `miniapp/` не тронут |
| A1-8 | Маршруты из спецификации | Hash-роутинг покрывает `#/` (Home), `#/oracle`, `#/people`, `#/people/:id`, `#/people/:id/timeline`, `#/settings`, `#/memory`, `#/chart`, `#/reading/:id`; неизвестный маршрут отдаёт экран 404, а не пустоту |
| A1-9 | Preview-данные обозначены | Каждый placeholder-экран несёт видимую пометку «демо-данные»; ни один компонент не имитирует успешный API-ответ (нет фейковых задержек и подтверждений сохранения) |
| A1-10 | Границы этапа соблюдены | `git status` — изменения только в `frontend-v2/` и `docs/product-v2/`; backend, `miniapp/`, миграции, CI, зависимости не тронуты |

## 2. Этап 2 — Сквозной чат

| ID | Критерий | Проверка |
|---|---|---|
| A2-1 | Единая точка отправки | Grep по фронту: все вопросы идут через `POST /api/chat/oracle`; обращений к `/api/chat/{agent}` с другим `agent` нет |
| A2-2 | Авто-роутизация работает | Вопрос «вытяни карты на отношения» → в ответе `routing.agent == "tarot"`, `routing.auto_route == true` |
| A2-3 | Астрология ревлется | Вопрос «что мой Сатурн говорит о работе» → `routing.agent == "astro"` |
| A2-4 | Неоднозначность не роутится молча | Вопрос с двумя жёсткими доменами → остаётся у `oracle`, `reason` содержит уточнение |
| A2-5 | Ответ содержит полный payload | В ответе есть `routing`, `proof`, `thread_id`, `charge`, `allowance` |
| A2-6 | Идемпотентность | Повтор с тем же `X-Idempotency-Key` не списывает лимит повторно |
| A2-7 | Dev-запросы работают без CORS | Запросы через Vite dev proxy (`/api` → `localhost:8080`) успешны; в проде `CORSMiddleware` по-прежнему отсутствует |
| A2-8 | Не изоляция пользователей | Два разных пользователя не видят ответов друг друга (кросс-юзер тест) |
| A2-9 | Кризисный путь | Кризисный текст → `safety` в ответе, лимит не списан, LLM не вызван |

## 6. Этап 6 — Память с графом

| ID | Критерий | Проверка |
|---|---|---|
| A6-1 | Consent off блокирует запись | Тест: `memory_enabled=0` → инструмент возвращает «память выключена» |
| A6-2 | Consent через UI | Выключение в `/settings` немедленно останавливает новую запись |
| A6-3 | Просмотр/правка/удаление | `GET`/`POST`/`DELETE /api/memories` + `DELETE /api/memory-links/{id}`; контракты 13 новых эндпоинтов — `API_CONTRACTS.md` §11 |
| A6-4 | Изоляция | Кросс-юзер тест на всех новых endpoint'ах |
| A6-5 | Сохранённое ≠ предположение | Тест `N-10`: `source_kind='user'` и `'derived'` различимы в ответе API; `POST /api/events` **не принимает** `source_kind='derived'`; UI не может создать связь с `origin='derived'` (422) |
| A6-6 | Обратная совместимость | Существующие `memories` без `source_kind` читаются как `'user'` |
| A6-7 | Удаление аккаунта полное | `POST /api/account/delete` → 0 строк в `memories`, `memory_links`, `personal_events`, `partners`, `tarot_readings`, `diary` |
| A6-8 | Timeline корректен | Группировка по месяцам; удалённая запись не ломает страницу |

## 9. Продуктовые критерии (что мы реально проверили)

| ID | Критерий | Проверка |
|---|---|---|
| P-1 | Пользователь не выбирает проводника | Сквозной прохождение всех 4 вкладок и 8 маршрутов (`UX_FLOWS.md` §0) без единого экрана выбора агента |
| P-2 | Первый инсайт персонален | Новый пользователь получает результат, зависящий от его данных, а не общий текст |
| P-3 | Память контролируется | Создать → увидеть → исправить → удалить факт; выключить память целиком |
| P-4 | Таро — опыт | Расклад: раздача → поочерёдное открытие → трактовка, с корректным reduced-motion |
| P-5 | История отношений | Добавить человека → связать факт → увидеть в Timeline |
| P-6 | Возрастной гейт на платном контенте | Тест `N-15`: без `age_confirmed_at` → `active_user`-ручки (`/api/today`, `/api/compat/full`, `/api/synastry`, `/api/composite`, `/api/transits`, `/api/returns`, `/api/chart/pdf`) отдают 402; с подтверждением → 200. Read-ручки (`/api/me`, `/api/chat/oracle`, `/api/chart`) **не гейтируются** — обратная совместимость существующих пользователей |
| P-7 | Подтверждение 16+ однократное | Тест `N-16`: `PATCH /api/profile {age_confirmed: false}` → 422; повторное `{age_confirmed: true}` идемпотентно. Самоподтверждение **не является** верификацией возраста — юридический вопрос открыт (`ARCHITECTURE.md` §5.1) |
| P-8 | Onboarding возобновляется | Тест `N-17`: прерванный на шаге 3 онбординг при повторном входе открывается на шаге 3; при `me.onboarded === true` онбординг недостижим |

## 10. Что НЕ является доказательством

- Снимок экрана без данных из реального API.
- «Тесты зелёные» без вывода команды.
- Локальный успех как доказательство production-готовности (`docs/RELEASE/CURRENT_STATUS.md` прямо фиксирует PRODUCTION = NOT CERTIFIED).
- Старые отметки в `PRODUCTION_GAUNTLET.md` / `PRODUCTION_FINAL_REVIEW.md` — они описывают удалённый SQLite и датированы 2026-08-27.
