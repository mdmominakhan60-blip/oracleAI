# OracleAI v2 — Screen Specification

15 экранов. Предварительный перечень, а не требование сделать 15 отдельных страниц: часть экранов — полноценные маршруты, часть — bottom sheets и диалоги внутри другого экрана. Классификация дана явно.

Контракты API — `API_CONTRACTS.md`. Потоки и переходы — `UX_FLOWS.md`. Токены — `DESIGN_SYSTEM.md`.

---

## Классификация экранов

**Навигация — четыре нижние вкладки:** `Home` · `Oracle` · `People` · `Me`. Всё остальное — внутри них.

| # | Экран | Тип | Почему так |
|---|---|---|---|
| 1 | Welcome | **Маршрут** `/` (первый вход) | Единственный экран до авторизации; показывается один раз |
| 2 | Onboarding | **Маршрут** `/onboarding` | Линейный процесс с шагами и валидацией; требует отдельной глубины |
| 3 | Birth Profile | **Шаг внутри Onboarding** + отдельная секция в `/settings` | Один раз при знакомстве; дальше правится в настройках |
| 4 | First Insight | **Состояние Chat** (не маршрут) | Первый ответ Oracle рисуется в том же чате; отдельная страница = лишний переход |
| 5 | Home | **Вкладка 1** `/` | Персональная сводка и быстрые действия; **не чат** |
| 6 | Oracle Chat | **Вкладка 2** `/oracle` | Единый диалог: список сессий + лента + композатор |
| 7 | People | **Вкладка 3** `/people` | Список людей + навигация; требует места |
| 8 | Person Profile | **Маршрут** `/people/:personId` (sheet на мобильном, раскрывается на планшете) | Один человек; sheet экономит переход, маршрут даёт ссылку |
| 9 | Relationship Timeline | **Маршрут** `/people/:id/timeline` | Хроника требует полного экрана |
| 10 | Tarot Spread Selector | **Bottom sheet** над Chat | Выбор расклада — минута, не маршрут |
| 11 | Tarot Reading Result | **Сцена внутри Chat** + маршрут `/reading/:id` для истории | Живой процесс и пересмотр — разные задачи |
| 12 | My Chart | **Маршрут** `/chart` (не вкладка) | Визуализация требует места; вход из Home и из Oracle |
| 13 | My Patterns / Memory | **Маршрут** `/memory` (не вкладка) | Управление данными; вход из ME и из Oracle |
| 14 | Paywall | **Bottom sheet** (модальный) | Прерывает поток, не должен быть адресуемым |
| 15 | Me / Settings | **Вкладка 4** `/settings` | — |

Итого **4 вкладки + 8 маршрутов внутри них** + 2 sheet'а + сцены в чате. Это сознательно меньше 15 страниц: каждая дополнительная страница — потеря контекста в продукте, где всё есть продолжение одного разговора.

**Что НЕ является нижней вкладкой:** натальная карта (`/chart`), Таро (сцена в чате), память (`/memory`), таймлайн (`/people/:id/timeline`), платёжный экран. Навигация из четырёх табов остаётся стабильной — пользователь никогда не теряет точку возврата.

## 1. Welcome

**Цель:** за 8 секунд объяснить: здесь один Oracle, который помнит. Не загрузка, не карусель.

**Структура сверху вниз:**
1. Фон `welcome` — космос, туман, созвездия (`22-background-states.css`).
2. Заголовок: «Один Оракул, который тебя помнит».
3. Одна фраза: «Спрашивай о чём угодно — картах, карте, отношениях. Я помню, что мы уже разобрали».
4. Одна кнопка: «Начать».
5. Строка 16+ внизу.

**Управление:** одна кнопка. Кнопка «назад» Telegram скрыта.

**Поведение:** тап → `POST /api/auth/session` → `GET /api/me`. Успех → Onboarding (если `onboarded=false`) или Chat. 401 → состояние ошибки с объяснением «открой из Telegram».

**Состояния:**
| Состояние | Вид |
|---|---|
| Загрузка | Фон + лёгкая пульсация кнопки, без спиннера |
| Ошибка 401 | «Открой OracleAI из Telegram» + кнопка повтора |
| Ошибка 5xx | Нейтральный текст + повтор |
| Успех | Переход на Onboarding или Chat |

**API:** `POST /api/auth/session`, `GET /api/me`.

**Приёмка:** при `onboarded=true` Welcome не показывается; кнопка одна; строка 16+ видна на Welcome.

## 2. Onboarding

**Цель:** получить контекст для первого персонального ответа. Не анкета ради анкеты.

**Ключевое отличие от v1:** v1 спрашивал intent из четырёх агентов (`miniapp/js/18-onboarding.js`). В v2 такого шага нет — спрашиваем одну открытую вещь.

**Шаги:**
1. **Что свелось тяжелее всего** — свободный ввод + 3–4 подсказки (отношения / решение / усталость / тревога). Это первое сообщение Oracle.
2. **Дата рождения** — с явным выбором: знаю точно / примерно / не знаю.
3. **Время и город** — только если шаг 2 = «знаю точно» или «примерно». Автодополнение города через `GET /api/city/suggest`.
4. **Образ Oracle** — 3 персоны: `friend` 🌸 / `witch` 🔮 / `mentor` 🕉 (`GET /api/personas`). Это **тон**, не персонаж.
5. **16+** — подтверждение «мне 16+», **обязательный шаг**: без него `onboarding_complete` не выставляется и платный контент (`active_user`) недоступен. Детали и открытый юридический вопрос — `ARCHITECTURE.md` §5.1.

**Поведение кнопок:**
- «Дальше» — валидирует шаг, при ошибке показывает причину под полем, ввод не теряется.
- «Пропустить» — всегда доступна, кроме шага 1 и шага 16+. Онбординг не становится платой за ценность.
- Каждый шаг — `PATCH /api/profile` **сразу после перехода** (с `onboarding_step`), не в конце. Финальный — с `onboarding_complete: true`.
- Возобновление — при входе читается `me.onboarding_step`; шаг с непустым `onboarding_step` открывается там, где остановились, а не с начала.

**Состояния:** загрузка (прогресс-сегменты), ошибка города (инлайн, ввод не теряется), ошибка отправки (сохраняем ответы, предлагаем повтор), успех → First Insight, повторный вход с `me.onboarded === true` → онбординг не открывается.

**API:** `GET /api/personas`, `GET /api/city/suggest?q=`, `PATCH /api/profile`.

**Приёмка:** ни один шаг не предлагает выбор проводника; «Пропустить» работает (кроме шага 1 и 16+); частично заполненный профиль сохраняется; прерванный онбординг возобновляется с того же шага; при `me.onboarded === true` экран недостижим.

## 3. Birth Profile

**Цель:** корректный ввод данных рождения с честной маркировкой точности.

**Три режима** (влияют на всё, что дальше):
| Режим | `birth_time_precision` | Что считается | Что видит пользователь |
|---|---|---|---|
| Точное время + город | `exact` | Полная карта: дома, ASC, MC, аспекты | Всё |
| Только дата | `unknown` | Знаки, стихии, управители. Дома и ASC/MC не считаются | Честное «без времени — без домов» |
| Приблизительное время | `approx` | Расчёт есть, но помечен как приблизительный | Предупреждение + кнопка «уточнить» |

**Структура:** дата (календарь/поле) → переключатель точности → время (если применимо) → город с автодоплнением → живое пояснение, что именно увидит.

**Управление:** переключатель точности меняет состав полей без потери введённого; «Не знаю время» → `unknown`.

**Состояния:** город не найден (инлайн, ввод сохранён), дата вне 1900..сегодня (400 с человеческим текстом), успех → пересчёт карты.

**API:** `POST /api/chart` (`ChartBuildIn`: `birth_date`, `birth_time`, `birth_time_precision`, `birth_city`), `GET /api/city/suggest`.

**Приёмка:** при `unknown` UI не рисует дома/ASC/MC; `approx` показывает предупреждение; ошибка не сбрасыв���т поля.

## 4. First Insight

**Цель:** первый настоящий результат. Не заглушка.

**Тип:** состояние внутри Chat — первое сообщение Oracle. Показывается **один раз**, сразу после онбординга.

**Когда показывается:**
| Условие | Поведение |
|---|---|
| `me.onboarded === false` → онбординг завершён | Показать First Insight |
| `me.onboarded === true` (вернувшийся пользователь) | **Не показывать.** Пользователь попадает на Home; Welcome/Onboarding/First Insight не всплывают |
| Пользователь вернулся и уже задавал вопросы | Не показывать — First Insight это первое сообщение треда, а не повторяемый экран |

**Логика выбора контента:**
- Есть карта (`chart_mode == "full"`) → один сильный аркан Матрицы (`GET /api/matrix`) + один понятный аспект личности из `sections.identity`.
- Нет карты → один Таро-опросник → `POST /api/tarot/draw?spread=one` → одна карта + одна фраза трактовки (`POST /api/tarot/interpret/{id}`).

**Структура:** приветствие (1 строка) → главный результат (крупно, визуально) → 2–3 поясняющие строки → один вопрос обратно → по заданному вопросу переход на **Home** (вкладка 1), не на вкладку Oracle.

**Приёмка:** не показывает 20 планет; ведёт к вопросу, а не к выгрузке прогноза; работает в обоих режимах (с картой и без); при `me.onboarded === true` не показывается; после вопроса пользователь оказывается на Home, а не автоматически в чате.

## 5. Home (вкладка 1)

**Цель:** ответить «что сейчас со мной и чем займусь прямо сейчас». Это **не чат и не дашборд с плитками** — экран собирает ровно персональное и даёт быстрые действия.

**Структура сверху вниз:**
1. **Приветствие** по имени + «ты была здесь N дней назад» (`global_streak`).
2. **Карта дня** — одна карта Таро (`today.card`), тап → переворот + короткая трактовка. Один аркан, не расклад.
3. **Лунный ориентир** — фаза, лунный день, одна фраза совета (`today.moon`, `moon/week`).
4. **Что Oracle помнит сейчас** — 2–3 факта (`me.memories`) + ссылка в `/memory`. Выжимка, не весь список.
5. **Быстрые действия** — крупные кнопки: «Спросить Oracle» → вкладка 2; «Вытянуть карты» → вкладка 2 с предзаполненным запросом; «Моя карта» → `/chart`; «Люди» → вкладка 3.
6. **Следующий шаг** (`today.next_action`) — серверная рекомендация по недостающему контексту.

**Визуальная иерархия:** карта дня — визуальный якорь экрана; быстрые действия — крупные области ≥48px; текст — короткие блоки, ни одного длинного абзаца (длинные тексты живут в Oracle).

**Управление и поведение:**
| Элемент | Действие |
|---|---|
| «Спросить Oracle» | Переход на вкладку 2, фокус в композатор |
| «Вытянуть карты» | Вкладка 2 с предзаполненным вопросом; сцена Таро — внутри диалога |
| «Моя карта» | `/chart` |
| Тап по карте дня | Переворот (130мс + 550мс) + трактовка (`interpret`) |
| Тап по факту | `/memory` |
| Прокрутка | Единственный жест; свайп-навигация отключён |

**Состояния:**
| Состояние | Вид |
|---|---|
| Загрузка | Скелетон карты дня + скелетон списка фактов |
| Ошибка | Нейтральный текст + повтор; уже загрузившееся сохраняется |
| Пусто (новый пользователь) | Не пустой экран, а «Начнём?» → онбординг / первый вопрос |
| Нет подписки (402) | Сводка работает, `/api/today` деградирует частично — показываем доступное, не пустой экран |
| Память выключена | Блок «помню» заменён на плашку «Включить память» |

**API:** `GET /api/me`, `GET /api/today`, `GET /api/moon/week`, `POST /api/tarot/draw`, `POST /api/tarot/interpret/{id}`.

**Приёмка:** на Home **нет** ленты диалога и композатора; карта дня переворачивается; все 4 кнопки ведут в заявленные адреса; при 402 экран не пустеет.

## 6. Oracle Chat (вкладка 2)

**Цель:** главный разговорный экран. Пользователь открывает и говорит; сцены Таро и карты возникают внутри диалога.

**Структура сверху вниз:**
1. **Шапка:** имя Oracle (настраиваемое `oracle_name`), индикатор памяти (включена/выключена), кнопка сессий.
2. **Лента диалога:** сообщения пользователя справа, ответы Oracle слева. Абзацы ≤4 строки, финальный шаг выделен.
3. **Композатор:** растущее поле, отправка, отмена, идемпотентность.
4. **Навигация:** 4 нижние вкладки (Home / Oracle / People / Me).

**Визуальная иерархия:** ответ Oracle — самый крупный текст экрана (`font-size-body-lg`, `max-width: 34em`). Доказательная подпись (`proof.tools_used`) — мелкая, ненавязчивая. Домен **не называется как персонаж**.

**Управление и поведение:**
| Элемент | Действие |
|---|---|
| Отправка | `POST /api/chat/oracle` c `X-Idempotency-Key` |
| Отмена | `AbortController`; вопрос уходит в черновик |
| Ретрай ошибки | Тот же ключ → идемпотентно |
| Свайп по ленте | Только прокрутка; свайп-навигация отключён в зоне чата |
| Тап по `proof` | Раскрывает, какие инструменты использованы (доверие, не отладка) |
| Кнопка сессий | Список: создать / выбрать / архивировать |

**Сцены внутри чата** (по `routing.agent` + `proof.tools_used`):
- `tarot` → `<TarotDeck>` (§11)
- `astro` / матрица → карточка аспекта с переходом на `/chart`
- `memory` → блок «я помню…» со ссылкой в `/memory`
- `chiromant` → предложение прислать фото

**Состояния:**
| Состояние | Вид |
|---|---|
| Загрузка | «Oracle думает» + фазы; не спиннер |
| Пусто | 3 живых сценария-стартера, не «начните диалог» |
| Ошибка | Нейтральный текст + повтор; черновик сохранён |
| Лимит | «Вопросы на сегодня кончились» + мягкий переход в Paywall |
| Кризис | Ответ поддержки с контактами помощи; обычный пузырь не используется |

**API:** `POST /api/chat/oracle`, `GET /api/me`, сессии `/api/chat/oracle/sessions*`.

**Приёмка:** нет кнопок выбора агента; `auto_route` не показывает «передала вопрос Урании»; ошибка сохраняет ввод; кризисный ответ визуально отличается.

## 7. People (вкладка 3)

**Цель:** люди как управляемая система, не справочник.

**Структура:** список карточек (имя, связь, «что нового»: число чтений/фактов/событий) → действия «+ добавить», тап → Person Profile.

**Управление:** «+ добавить» → sheet (имя, связь, дата рождения опционально). Тап по карточке → sheet. Долгое нажатие → удаление с подтверждением.

**Состояния:** пусто («Расскажи о нём — я запомню»), память off (плашка «включить память»), ошибка удаления (откат + повтор).

**API:** `GET /api/people` (новый, `ARCHITECTURE.md` §4.3), `POST /api/people`, `DELETE /api/people/{id}`.

**Приёмка:** чужой `personId` → 404 (единый ответ с несуществующим); удаление предлагает, что произойдёт со связями.

## 8. Person Profile

**Цель:** один человек и всё, что с ним связано.

**Цель:** один человек и всё, что с ним связано.

**Структура сверху вниз:** шапка (имя, связь, действия) → «Что я знаю» (факты, привязанные к человеку; сохранённые ≠ предположенные — разные маркеры) → «Наши чтения» (расклады с его участием) → «Разговоры» (**только метаданные**: `title`, `messages_count`, `preview=""`; текст переписки не отдаётся) → действия: совместимость / спросить Oracle / удалить.

**Управление:** каждое действие — явная кнопка с предсказуемым результатом. «Спросить Oracle» открывает Chat с предзаполненным вопросом.

**Состояния:** нет фактов («пока ничего не запомнила»), нет чтений, память off (read-only режим: видно, но не пишется).

**API:** `GET /api/people/{id}`, `POST /api/compat`, `POST /api/compat/full`.

**Приёмка:** факты с `source_kind='derived'` визуально отличаются от `'user'`; совместимость использует существующий контракт баллов.

## 9. Relationship Timeline

**Цель:** обратная хроника по линии отношений.

**Структура:** группировка по месяцам (новые сверху). Тип записи помечен иконкой и подписью: событие / чтение / факт / запись дневника. Фильтры по типу.

**Управление:** тап по записи → свой источник (расклад, запись, факт). Фильтр — чипы сверху.

**Состояния:** пусто, ошибка загрузки, частичные данные (если запись удалена — не падаем, показываем «удалено»).

**API:** `GET /api/people/{id}/timeline` (новый), `GET /api/history`.

**Приёмка:** удалённая запись не ломает линию; группировка корректна на границе месяцев; только метаданные, приватный контент не тянем.

## 10. Tarot Spread Selector

**Цель:** выбрать расклад, понимая, что получишь.

**Тип:** bottom sheet над Chat.

**Структура:** 10 раскладов карточкой (emoji, название, число карт, positions в свертнутом виде, tier). Включённые в тариф — обычным видом; премиум — с ценой (`price_stars` / `price_crystals`) и признаком `owned`. Поле вопроса (обязательно). Deck: `tarot` / `lenormand`.

**Управление:** выбор карточки → фокус на поле вопроса. «Тянем» → `POST /api/tarot/draw`.

**Состояния:** загрузка (тасовка, не спиннер), отказ доступа (`ChatDenied` → Paywall с ценой), ошибка сети (повтор, вопрос сохранён).

**API:** `GET /api/tarot/spreads`, `GET /api/tarot/spreads/full`, `POST /api/tarot/draw`.

**Приёмка:** цены только из API, не захардкожены; `included` не подписан как бесплатный; вопрос обязателен.

## 11. Tarot Reading Result

**Цель:** визуальный опыт с доказательством честности.

**Тип:** сцена внутри Chat + адресуемый маршрут `/reading/:id` для истории.

**Структура:** позиции подписаны → N карт рубашкой вверх в сетке → открытие по порядку → прогресс-бар → все открыты → «Что это значит» → трактовка + один шаг.

**Анимация:** раздача `dealIn` стаггер 80мс; тап → 130мс приподнимание → 550мс `rotateY(180deg)`; следующая карта «дышит» (`tarotNextCard` 1.8s). При `prefers-reduced-motion` — мгновенное открытие, конечный поворот сохранён.

**Поведение:** открытие строго по порядку с мягкой подсказкой (не запретом); `onError` на картинке → fallback `card-face.jpg`; перевёрнутая карта показывается поворотом арта (в v1 был только бейдж — фиксим).

**Состояния:** загрузка draw, загрузка interpret (карты уже видны), ошибка interpret (карты остаются, повтор), пустая история, отмена.

**API:** `POST /api/tarot/draw`, `POST /api/tarot/interpret/{id}`, `GET /api/tarot/history/{id}`, `POST /api/tarot/outcome/{id}`.

**Приёмка:** порядок открытия соблюдается мягко; reduced-motion работает; `onError` есть; трактовка не отображается до завершения раскрытия.

## 12. My Chart

**Цель:** астрологическая визуализация, не таблица.

**Структура:** SVG-колесо (планеты, знаки, дома, аспектные линии) → 3 акцента («самое заметное») из `sections` → действия: Матрица / разбор / совместимость.

**Управление:** тап по планете → bottom sheet с человеческим объяснением; зум/пан на touch.

**Состояния:** загрузка (скелетон колеса), пусто (запрос даты прямо на экране), недостаточная точность (объяснение + «уточнить время»), ошибка расчёта.

**API:** `GET /api/chart`, `GET /api/chart/image` (fallback для share), `GET /api/matrix`, `POST /api/chart/interpret`.

**Приёмка:** при `precision != exact` дома и ASC/MC не рисуются; `approx` помечен; колесо — inline SVG без растровых картинок.

## 13. My Patterns / Memory

**Цель:** продуктовая отстройка — пользователь видит и управляет памятью.

**Структура:** переключатель памяти → «Что ты обо мне знаешь» (факты по `kind`, каждый: править / удалить / отвязать от человека) → «Что я замечаю» (синтез сохранённого, помечен как наблюдение) → «Люди и события» → «Экспорт» / «Удалить всё».

**Управление:** переключатель памяти — немедленный `PATCH /api/profile {memory_enabled}` с объяснением последствий. Каждый факт — точечное действие.

**Состояния:** пусто (3 примера + призыв), память off (объяснение, что именно не работает, read-only), ошибка удаления (откат), ошибка загрузки.

**API:** `GET /api/memories`, `POST /api/memories`, `DELETE /api/memories/{id}`, `GET /api/memory/context`, `PATCH /api/profile`, `GET /api/account/export`.

**Приёмка:** `source_kind='user'` и `'derived'` визуально различимы; выключение памяти немедленно прекращает новую запись; экспорт работает; удаление одного факта не удаляет остальное.

## 14. Paywall

**Цель:** объяснить, а не заблокировать.

**Тип:** модальный bottom sheet.

**Структура:** «Что именно кончилось» (вопросы сегодня / конкретный расклад / разбор) → разница тарифов (`GET /api/shop`) → action (кристаллы / подписка) → «Не сейчас».

**Управление:** покупка **никогда** не выдаётся из Mini App: создаётся заказ и ссылка (`POST /api/shop/invoice` → `openInvoice` / `openLink`); fulfilment приходит боту.

**Состояния:** успех создания заказа, ошибка PSP, отказ («Не сейчас» не исчезает и не уменьшается).

**API:** `GET /api/shop`, `POST /api/shop/invoice`, `POST /api/shop/web-checkout`, `POST /api/shop/crystals`, `GET /api/entitlements`.

**Приёмка:** paywall не появляется до первого полезного ответа; называет конкретную причину; «Не сейчас» равна видима с главной кнопкой.

## 15. Me / Settings (вкладка 4)

**Цель:** профиль, тон, память, оплата, приватность — в одном месте.

**Структура:** профиль (имя, город, дата/время, точность) → образ Oracle (3 персоны) → память (переход + переключатель) → приватность (`GET /api/account/privacy`) → экспорт → уведомления → подписка и заказы → удаление аккаунта.

**Управление:** каждое изменение — явное сохранение с подтверждением. Удаление аккаунта — отдельный экран с предупреждением и подтверждением.

**Состояния:** сохранено (подтверждение), ошибка сохранения (повтор, данные не потеряны), удаление (идемпотентно; повтор → `already_deleted`).

**API:** `GET /api/me`, `PATCH /api/profile`, `GET /api/personas`, `GET /api/account/privacy`, `GET /api/account/export`, `POST /api/account/delete`, `GET /api/shop/orders`, `GET/PATCH /api/notifications/preferences`.

**Приёмка:** изменение `memory_enabled` видно сразу; экспорт отдаёт реальный файл; удаление требует `{confirm:true}` и идемпотентно.

## Сквозные требования (все экраны)

**Адаптивность:** mobile first (вебвью телефона). Планшет: Person Profile раскрывается в маршрут. Desktop: контейнер ≤1680, поля ≥24. Safe-area через токены `--safe-top/bottom`.

**Доступность:**роли + `aria-live` для ответов Oracle; focus-trap в sheet/модалках; Esc; target ≥44×44; success/error всегда с текстом и значком, не только цветом; `prefers-reduced-motion` отключает все движения.

**Анимации:** длительности только из токенов (`--motion-quick/base/slow`, `--tarot-*`). Не более 4 непрерывных фоновых анимаций (R03). Никакой анимации на тексте ответа — читаемость важнее.

**Ошибки:** единый формат — человеческий текст + «Попробовать снова»; без кодов и стектрейсов; `friendlyError` из `01-utils.js:231-244` переносится и расширяется. Черновик ввода никогда не теряется.

**Пустые состояния:** всегда один живой призыв к действию, никогда «Данных нет».
