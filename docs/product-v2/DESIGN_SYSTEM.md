# OracleAI v2 — Design System

Направление: **premium dark celestial**. Глубокий индиго, мягкий фиолетовый туман, античное золото, выразительная типографика с работающей кириллицей, аккуратные созвездия, минимум визуального шума и максимум читаемости длинных AI-ответов.

**Главный принцип:** мистика дополняет интерфейс, но никогда не мешает задаче. Если атмосфера мешает прочитать ответ — атмосфера проигрывает.

---

## 1. Источник токенов: один

В старом проекте **четыре источника токенов**, и это породило реальные баги. Решение v2: **один канон** — дизайн-токены R03 + их реализация `miniapp/css/00-tokens.css`, перенесённые в TS-слой как единственный источник. Никаких новых hex вне файла токенов.

Что обнаружено в старом проекте и что мы делаем:

| Проблема | Где | Решение v2 |
|---|---|---|
| **CSS-цикл** — гарантированно невалидное свойство | `miniapp/css/24-r06-tokens.css:10` задаёт `--color-bg: var(--color-bg-primary)`, а `00-tokens.css:55` задаёт `--color-bg-primary: var(--color-bg)` | Удалить цикл; одна направленная связь |
| **Вторая палитра**, перекрывает всё (импорт последний) | `miniapp/css/27-observatory.css:5-22`: `#101222` вместо `#0B0D18`, `#dec59b` вместо `#E9C982`, nav 72px вместо 66 | Один набор цветов; observatory использует те же токены |
| **34 hex в JS против 24 в CSS** | `05-app.js`, `08-widgets.js`, `11-compat.js`, `02-art.js` | Все цвета только из токенов |
| **Три противоречивые копии палитры агентов** | `05-app.js:679-682`, `06-home.js:208-211`, `03-data.js:51-54` — расходятся в 3 из 4 значений | Нет агентов ⟹ нет per-agent палитр |
| Старые документы описывают **до-R03** палитру (13+ расхождений) | Удалённые `docs/DESIGN_SYSTEM.md`, `docs/DESIGN_COMPONENT_INVENTORY.md` | Новый документ = канон; старые документы удалены |
| Гейт проверяет только **наличие** токенов, не значения | `scripts/check_design_contract.py` | Сверять значения с этим документом |

### Добавление v2: фиолетовый туман

Визуальная концепция требует «мягкий фиолетовый туман». В R03 аметист удалён (`--color-accent-secondary` перенаправлен на нейтральный `#B7BDCB`, см. `00-tokens.css:61-63`). Для тумана вводится **одна** новая производная группа — не цвета, а фоновые слои:

```
--mist-1: radial-gradient(ellipse at 20% 10%, rgba(124, 92, 196, .18), transparent 55%)
--mist-2: radial-gradient(ellipse at 85% 80%, rgba(88, 74, 158, .14), transparent 60%)
```

Ограничения: туман **только фон**, никогда не текст и не бордер; opacity держится ниже порога, при котором падает контраст текста; при `prefers-reduced-motion` туман становится статичным.

### Запреты

- Новые hex вне файла токенов.
- Пятая непрерывная цветовая анимация (R03 §2.1).
- Светящиеся постоянные контуры у обычных карточек — тень од¾ на overlay (урок BUS-712).
- Ручное копирование градиента в селекторах.

Шрифты уже vendored'ы и имеют работающую кириллицу: **Manrope** (основной, woff2 с cyrillic-субсетом, preload в `miniapp/index.html:16`), Cinzel и Plus Jakarta Sans как fallback.

Строки: `--line-height-display: 1.08`, `--line-height-body: 1.55`. Трекинг: `--tracking-display: -.01em`, `--tracking-label: .08em`.

### Ключевое требование v2: читаемость длинных AI-ответов

Это главная типографическая задача продукта, и в старом интерфейсе она решалась слабо. Требования:

- Ответ Oracle рендерится при `font-size: var(--font-size-body-lg)` (16px) и `line-height: var(--line-height-body)` (1.55). Не меньше 14px никогда.
- **Абзацы ≤ 4 строки** на мобильном. Длинные ответы разбиваются: короткий ведущий абзац → 2–3 блока с подзаголовками → один конкретный шаг в конце.
- Ширина строки ограничена: `max-width: 34em` для текста ответа.
- Контраст: `--color-text-primary` (`#F4F2ED`) на `--color-surface` (`#141827`) — запас выше AA (R03 §2.4, проверено WCAG 2.2 AA 2026-09-10).
- Второстепенный текст (`--color-text-secondary`) — только для пояснений и меток, не для основного ответа.

| `--touch-target` | 44px | Минимальная область нажатия |

Сетка: gutter 16 (mobile) / 24 (desktop), боковые поля ≥24 (desktop). Контейнер ≤1680.

## 5. Motion

| Токен | Значение |
|---|---|
| `--motion-quick` | 140ms |
| `--motion-base` | 220ms |
| `--motion-slow` | 480ms |
| `--ease` | `cubic-bezier(0.22, 1, 0.36, 1)` |
| `--motion-ritual` | `cubic-bezier(.22, .9, .24, 1)` |

**Требование v2:** все тайминги — только токены. В старом коде значения захардкожены прямо в CSS/JS (130мс приподнимание, 550мс переворот, 80мс стаггер, 750мс каскад). Переносим значения, но выносим в токены:

```
--tarot-lift:      130ms   /* приподнимание карты перед переворотом */
--tarot-flip:      550ms   /* сам rotateY(180deg) */
--tarot-deal-step:  80ms   /* стаггер раздачи */
--tarot-cascade:   120ms   /* шаг ритуального каскада */
--tarot-breathe:  1800ms   /* «дыхание» следующей карты */
```

## 7. Компоненты

Принцип: компонент существует, только если решает задачу. Не строить «библиотеку на вырост» — 15 экранов требуют ограниченного набора.

### 7.1 Базовые
`Button` (primary / secondary / ghost, размеры sm/md/lg), `IconButton`, `Field` (текст/дата/автодополнение), `Sheet` (bottom sheet, imperative+declarative API), `Modal`, `Toast` (2400мс), `Skeleton` (форма-специфичный: колода, колесо, список), `Segmented`, `Chip`, `Avatar`, `Divider`.

### 7.2 Чат
`OracleBubble` (ответ с абзацами, подзаголовками, финальным шагом), `UserBubble`, `Composer` (растущее поле, отправка, идемпотентность, отмена), `ThinkingStage` (фазы вместо спиннера), `ToolTrace` (доказательная подпись), `RoutingHint` (мягкая маркировка «посмотрела в карту»).

### 7.3 Таро (ядро визуального опыта)
`TarotCard` — props: `slug`, `deck`, `reversed`, `revealed`, `isNext`, `positionLabel`. Содержит: изображение `/static/img/{deck}/{slug}.jpg`, рубашку `/static/img/card-back.jpg`, 3D-переворот (см. §8), `onError` fallback. **В старом коде `onerror` на таро-картах отсутствовал** — это дефицит, который v2 исправляет.

`TarotDeck` — сетка расклада, порядок позиций, стаггер раздачи. `SpreadSelector` — витрина с tier.

### 7.4 Астрология
`ChartWheel` — inline SVG (переносится из `miniapp/js/10-chart.js`), без растровых картинок. `PlanetSheet` — bottom sheet по тапу на планету. `MatrixPanel` — арканы Матрицы Судьбы. `CompatPanel` — пары и домены.

### 7.5 Люди
`PersonCard`, `PersonList`, `TimelineGroup` (по месяцам), `FactChip` (с типом: факт/наблюдение), `MemoryConsentBanner`.

## 8. Анимация переворота карты (перенос дословно)

Источник: `miniapp/css/10-tarot-carousel.css:65-79` + `miniapp/css/15-ritual-redesign.css:1263-1266` + `miniapp/js/09-tarot.js:221-251`.

Механика: `.tcard` несёт `perspective: 1000px`; `.tcard-inner` — `transform-style: preserve-3d`, `transition: transform var(--tarot-flip)`; `.tcard.open .tcard-inner { transform: rotateY(180deg) }`; `.tcard-front` предповёрнут на `rotateY(180deg)`; обе грани — `backface-visibility: hidden`.

Хронолиния (Java-тайминги с портированы в CSS-токены):
1. Тап → `.is-turning` (`rotateY(11deg) scale(.975)`) на `--tarot-lift` (130ms).
2. Смена класса → переворот `--tarot-flip` (550ms).
3. Итого ≈680ms; затем подпись позиции проявляется (`fadeIn` .25s).

Раздача: `dealIn` — `from { translateY(-46px) rotateY(96deg) scale(.72); opacity: 0 }`, стаггер `--tarot-deal-step` (80ms), ease `cubic-bezier(.22,1,.36,1)`.

**Что не переносится механически:** раскрытие подписей сделано через sibling-селектор `~` (`10-tarot-carousel.css:90-98`) — в React нет аналога, заменяется на state-условие. В старом коде обновлялся DOM напрямую (без ререндера, чтобы не прыгал скролл) — в React это решается ключами и `useLayoutEffect`.

`prefers-reduced-motion`: конечное `rotateY(180deg)` сохраняется, переходы отключаются — карта открывается мгновенно (`15-ritual-redesign.css:1279-1290` + `11-misc.css:82-93`).

## 9. Доступность

- WCAG 2.2 AA, целевой минимум 24×24; внутренний стандарт 44×44.
- Контраст всех текстовых пар проверен (R03 §2.4).
- Роли и `aria-live="polite"` для появления ответа Oracle.
- `prefers-reduced-motion` — единый авторитетный блок, покрывающий все фоновые и ритуальные движения.
- Focus-visible ring (`--focus-ring`), focus-trap в модалках, Esc для закрытия.
- Клавиатурная навигация по картам и навигации.
- Никакой информации только цветом: success/error всегда с текстом и значком.
- Проверка через `axe-core` в CI (уже есть: `npm run test:axe`) и Lighthouse по 4 категориям (`npm run test:lighthouse`).
