# Нагрузочные тесты (G29)

Цифры сценариев — из оценки нагрузки в `docs/RELEASE/PRODUCTION_READINESS.md` §2.

## Состав

| Файл | Что нагружает | Целевые цифры |
|---|---|---|
| `scripts/seed_load.py` | генератор 10k фейк-юзеров (таймзоны, тарифы, онбординг) | `--count 10000` |
| `load/simulate.py` | бот-потоки: /start, утренний пик прогнозов, вопросы под семафором LLM, оплаты | 2000 / 4000 / 1000 / 100 |
| `load/locustfile.py` | API Mini App (READ-поток, 50 RPS) | p95 < 400 мс, кроме генераций |

## Запуск

```bash
# 1) база на 10k — фейк-юзеры в DATABASE_URL (отдельная тестовая БД, не прод)
python scripts/seed_load.py --count 10000

# 2) бот-сценарии (LLM в офлайне/стаб — меряем механику, не сеть провайдера)
python load/simulate.py                # быстрая проверка
python load/simulate.py --full         # целевые цифры G29

# 3) API Mini App — Locust, сервер в DEV_MODE (без подписи Telegram)
DEV_MODE=1 .venv/bin/python -m uvicorn app.api.main:app --port 8000
pip install locust
locust -f load/locustfile.py --host http://127.0.0.1:8000 -u 500 -r 5 --run-time 2m
```

## SLO из ТЗ, за которые отвечает каждый сценарий

| Сценарий | SLO | Где смотреть |
|---|---|---|
| 2000 конкурентных `/start` | ноль падений; гонка `users.ensure` не даёт дублей | `start_flood` |
| утренний пик 3000–4000 прогнозов | все прогнозы до 09:30 локального; офлайн фолбэк не ломает поток | `forecast_p35-4k` |
| 1000 одновременных вопросов | p95 < 10 с (включая очередь семафора LLM) | `question_1k` |
| 100 конкурентных оплат | ноль ошибок; каждая оплата выдаёт товар ровно один раз | `payment_100` + дельта прав |
| API 50 RPS | p95 < 400 мс (кроме генераций) | сводка Locust |

Прогон `--full` на dev-машине ~1–2 минуты при `--count 8000` (даёт ~4400
кандидатов на прогноз, сценарий берёт 4000).

> Известное ограничение: оплаты в сценарии идут на разных клиенток (проверяем
> пропускную способность и целостность выдачи). Гонка двух оплат за один товар
> и вебхук-идемпотентность покрыты юнит-тестами `tests/test_billing.py`.
