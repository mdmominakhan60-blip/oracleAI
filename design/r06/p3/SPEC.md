## 2. Что покрыто и по какому требованию

### 2.1 Сегодня S15 (план §9.2)
- Дата, один открытый прогноз/фокус, «Обсудить день» — главный CTA. Прогноз в `-webkit-line-clamp:3` с «Развернуть» без буквиц и обрыва в декоративной рамке.
- Три компактных блока: Карта дня, Луна недели, Дневник. Счётчиков практик нет при отсутствии данных — блок «Дневник» показывает честный empty («Сегодня ещё не записано»), не ноль-заглушку.
- Ни одного элемента paywall-ленты на Сегодня (§9.2, R02 §1.1: secondary без продажи).
- Desktop ≥768: блоки в 3 колонки; forecast-колонка остаётся одна (один основной результат).

### 2.2 Библиотека S20 (план §9.3)
- 3 таба сегмент-контролом (Разборы · Диалоги · Дневник) — таб = состояние раздела (R02 §2.1). Поиск сверху.
- Строка записи: иконка источника, название, дата, превью, источник + статус-бейдж («оплачен»). Табы Диалоги/Дневник — та же строка, одна модель данных.
- Устаревшая запись: inline-состояние «построен на старых данных» с выбором «Открыть как есть / Построить заново» — история не переписывается незаметно (§9.4-принцип, E15: открытие ≠ пересчёт ≠ списание).

### 2.3 Профиль S21 (план §9.4)
- Карточка профиля (имя пользователя ≠ oracle_name) + группы строк со значением справа: Данные и память / Тариф и оплата / Настройки / Помощь и данные.
- Подразделы — push-переходы с заголовком-«Назад» (R02 §2.1), не модалки: Память, Уведомления показаны полностью.
- Приглашения (+50 ✦) и Помощь — только реально существующие функции; «Удалить аккаунт» — danger-строка отдельной группой, без экспорта в ту же строку.

### 2.4 Память S22 (§9.4)
- Факты с источником («из разговора», «дневник») и датой; удаление — inline-подтверждение под фактом с последствиями («Лилит перестанет его учитывать. Это нельзя отменить»).
- Удаление памяти ≠ диалога ≠ аккаунта — разные операции; подтверждение не модальное, фокус остаётся в контексте.

### 2.5 Уведомления S23 (§9.4)
- Время уведомлений по текущему часовому поясу, подписано отдельно от города рождения (§9.1-различие зафиксировано в интерфейсе).
- Тумблеры — реальные checkbox с aria-label; «Пауза всех» — отдельный ряд с датой. Язык/анимация — соседний подраздел (reduced-motion уважает систему, R05 §3.3).

### 2.6 Тариф S24 (план §9.5)
- Баланс Кристаллов одной строкой с «Пополнить»; объяснение Кристаллов — обычной фразой. Без баланса в шапках чата и без рекламных лент.
- Текущий план: цена, состав, дата списания («11 октября · продление автоматическое») — все данные из серверного контракта (в макете демо-значения; FE берёт из /api/shop).
- Способы оплаты — одна форма (Telegram Stars / Крипто), без дублирующих экранов. Промокод — короткая ссылка, раскрывает поле (не отдельный экран).

### 2.7 Paywall S24-sheet и оплата S25–S26 (§9.5, R02 H6/H7)
- Paywall = sheet из ограничения доступа: return_to-плашка «вернёшься к разбору синастрии — черновик сохранён», «Не сейчас» — равноправный выход. Не ловушка, не отдельная вкладка.
- Ожидание оплаты: спиннер + «Счёт уже создан — не оплачивай повторно, даже если окно закрылось» + «Проверить статус». Pending ≠ failed (E17).
- Заказы: статусы Оплачен/Ожидает/Неизвестно/Отменён; «Неизвестно» имеет действие «Проверить статус» — не прячется под «ошибка, купите ещё раз» (S26).

### 2.8 Большой расклад S13 (план §6)
- Кельтский крест 10 позиций: сетка 5 колонок (mobile ≥360px, <360 — 3 колонки), те же карты колоды, нумерация позиций на клетках.
- Открытие по порядку позиций (вне порядка — блок, инлайн-подсказка); открытая клетка → увеличенный просмотр (S13c из p2). Список позиций — равнодоступная альтернатива в `<details>`: выбор без попадания в клетку, подписи не поверх схемы (§11.3).
- Подписи позиций уходят в список, клетки остаются чистыми — требование §11.3 «не показывать все длинные объяснения поверх схемы».

### 2.9 Матрица состояний §11.2
Кадры-образцы каждого класса на виде «states»: loading (skeleton-каркас), empty (объясняет следующий шаг), нет доступа (banner → paywall с сохранением черновика), ошибка сети (Повторить), session expired (не исчезает, Войти заново + Помощь), запись не найдена (deep link H10, возврат), ошибка поля (у поля, aria-describedby).
Элементные состояния (hover/focus-visible/pressed/disabled) — встроены во все компоненты пакетов. Toast — только краткие подтверждения; критические состояния входа/платежа — стойкие баннеры.

## 4. Доступность (R03 §8.2, WCAG 2.1 AA)
- Табы: role=tablist/tab/tabpanel, aria-selected, aria-controls; скрытые панели `hidden`.
- Тумблеры: checkbox + aria-label (именованные, клавиатурные), focus-visible ring на track.
- Подтверждение удаления: role=alertdialog inline; стейл-блоки ошибок — role=alert/status по критичности.
- «Позиции списком» — details/summary; клетки — button с aria-label «Позиция N, имя. Карта открыта/закрыта», aria-pressed.
- Поиск библиотеки и промокод — visually-hidden label; контраст текстов поверх surface-подложек.

## 6. Найти и фиксы (важно для Frontend)
1. **`.lib-stale__text` без `min-width:0` в flex-строке с иконкой** → текст с длинным заголовком раздувал строку до 326px; кнопки в `.lib-stale__actions` без flex-wrap не переносились. Фикс: `min-width:0` на текст + `flex-wrap:wrap` на действия. Грабля та же, что в p2: min-content flex-item = min-content контента.
2. **`-webkit-line-clamp` требует `-webkit-box-orient:vertical` и display:-webkit-box** — иначе clamp молча не работает и прогноз разворачивается полностью. В проде аналогичную clamp-функцию сверять на 320px.
3. **`role=alertdialog` inline без фокус-лупы** — в прототипе упрощение; в проде для подтверждений удаления использовать dialog с focus trap или подтверждение без role=alertdialog (паттерн R03).
4. **`replaceWith` для промокода** — прототипный приём; в проде состояние «промокод» — part of form state (восстановление после ошибки сети).

- Список нужных изображений для борда — в конце R06 (артефакт задачи, см. комментарий поставки).
