## 2. Что покрыто и по какому требованию

### 2.1 Онбординг S04 (план §9.1)
- **Шаг 1 — намерение**: три возможности («обсудить вопрос» / «разобрать карту» / «сделать расклад»), одно главное действие. Ветка астро ведёт через шаги 2–5; чат/таро требуют меньше данных (пометка в макете).
- **Шаг 2 — имя**: подсказка «можно изменить в профиле»; демо-состояние ошибки «минимум 2 символа».
- **Шаг 3 — дата**: три явных сегмента день–месяц–год (не колёсный помесячный picker). Hint про нижнюю панель и ручной ввод. Демо-ошибка «31.02.1994» с человеческой формулировкой.
- **Шаг 4 — время**: «Точно» (время), «Примерно» (интервал, без подстановки 14:00), «Не знаю» (отдельный признак). Пояснение ограничений — одна строка.
- **Шаг 5 — город**: combobox, до 5 подсказок (город крупнее, регион+страна ниже), loading-состояние, подтверждённая строка + «Изменить».
- **Проверка данных**: каждая строка с «Изменить» → возврат на нужный шаг, остальные сохранены. После «Начать разбор» — реальный результат, не экран «готово» (§9.1).
- **Прогресс**: сегментный (эталон R03 §4.4), фактическое число шагов ветки, метка «Шаг N из 5 · название».
- **Footer**: sticky; `hidden`-поля реально скрыты (глобальный `[hidden]{display:none!important}`).

### 2.2 Чат S05–S06 (план §4)
- **Шапка**: назад, аватар 36px, имя + краткая роль, одно меню «⋯». Без логотипа/баланса/тарифа/переключателя всех агентов (план §4.1).
- **Пустой чат**: портрет 64px, «С чего начнём?» + verbatim-greeting Лилит из R04 (`agent.yaml`), ровно 3 примера, подстановка текста без отправки.
- **Переписка**: ответ агента — спокойная поверхность без массивной рамки; заголовки и списки внутри ответа; пользователь — компактная подложка справа. Действия «Копировать / Ещё» видимы на touch (план §4.2).
- **Карточка результата в чате** (§5.4): название, мини-превью 56px, 2–3 строки, «Открыть» — без разворачивания всего разбора в ленте.
- **Composer**: покой ~80–112px; поле 1→5 строк (интернальный скролл дальше); placeholder «Напиши вопрос…»; кнопка «Инструменты» подписана; «Отправить» disabled при пустом поле (проверено пробой). Enter/Shift+Enter — desktop-поведение, помечено в заметке.
- **«Остановить»**: честная семантика — «Остановить получение ответа» (aria-label), появляется только в потоковом состоянии; без обещания отмены backend-работы (план §4.3).
- **Ошибка у сообщения**: остаётся при своём сообщении, «Повторить» ведёт повтор того же запроса, без двойного списания.
- **«Новое сообщение ↓»**: pivot-кнопка; автопрокрутка только у конца ленты (план §4.2).

### 2.3 Реестр состояний §11.2 (вид «chat-states»)
Покрыты и нарисованы: loading истории (skeleton-бабблы), ошибка сети с «Повторить», session expired (StatusBanner, не исчезает, «Войти заново»), нет доступа (banner → paywall, черновик сохранён), deep link на удалённый разбор («Разбор не найден» + возврат). Каждому состоянию — свой набор действий (реестр действий R02 §5.7). Полная матрица состояний S01–S30 — пакет 3.

### 2.4 Навигация (R02 §2, R03 §4.1)
- **BottomNav** mobile <768: 4 раздела, 64px + safe-area. Скрыт в открытом диалоге, виден на списках (R02 §2.1).
- **Rail** 768–1279: 72px.
- **Sidebar** ≥1280: 224px, бренд, «Новый разговор», разделы, недавние, профиль в футере.
- Медиазапросы: `.bottomnav` скрывается с 768, rail ↔ sidebar переключение на 1280.

### 2.5 Каталог инструментов S10 (план §5.1) — превью пакета 2
Sheet ≤80% высоты, заголовок+закрыть+поиск, недавние ≤3, категории, строка 64px (иконка 24 в тайле 40), состояния «недоступно сейчас»/«нужны данные» различаются текстом, «У другого специалиста» с именем и переходом без автопереключения. Полное покрытие §5.2–§5.4 — пакет 2.

## 4. Доступность (R03 §8.2, WCAG 2.1 AA)
- Контраст пар токенов проверен на этапе R03; фон-изображения — под surface, текст поверх поверхностей.
- Focus-visible: `--focus-ring` на всех интерактивных; порядок таба естественный.
- Комбобокс города: `role=combobox`, `aria-expanded`, `aria-controls`, `listbox`+`option`, `aria-autocomplete=list`.
- Прогресс: `role=progressbar` c `aria-valuenow` (обновляется скриптом прототипа).
- «Отправить»/«Остановить»/меню «⋯» — aria-label; примеры и интент-карточки — кнопки с состоянием `aria-pressed`.
- Ошибки: `role=alert` (msg__error, status-banner--error), поле ошибки связано `aria-describedby` + `aria-invalid`.
- Skipped-заголовки: visually-hidden label у поля ввода чата и поиска.

## 5. Верификация (выполнено)
- Headless Chrome: hash-навигация активирует правильный view для всех 6 видов (DOM-проверка).
- 320px probe (iframe 320px, замер `scrollWidth` + элементы за 320.5px): **0 переполнений на всех 6 видах** после фиксов (см. §6). До фиксов: onboarding 342px, sessions 533px.
- Интерактив: интент → шаг 2; «Продолжить» по шагам 2→3; «Примерно» открывает интервал, «Точно» скрывает; composer disabled↔enabled от текста. Лог пробы: `probe-steps.html` (результат в DOM).
- Скриншоты 320/768/1280 сняты в `/tmp/r06-shots/` (визуальная приёмка — за EL/FE на ревью).

## 6. Найти и фиксы (важно для Frontend)
1. **`hidden` против `display:flex`**: авторский `display` на `.onboarding__step` и `.session-card__top` перебивал атрибут `hidden` (UA-стиль слабее) → скрытые шаги онбординга оставались видимыми и давали переполнение. Фикс: глобальный `[hidden]{display:none!important}` в `styles.css:889`. **Перенести в прод-стили обязательно** — у нас это ловится на §11.2-состояниях.
2. **`.screen-view.is-active` был `display:flex` без направления** → `.screen` как row-child раздувался по контенту. Фикс: `flex-direction:column; width:100%; min-width:0` (styles.css:885).
3. **`.session-card__body`** (span) не был flex-контейнером → nowrap-превью растягивало карточку. Фикс: `display:flex; flex-direction:column; min-width:0` + `min-width:0` на `__top`/`__preview` (styles.css:745–749).
4. Headless Chrome игнорирует `--window-size` <500px — верификация ширины только через iframe-пробу (в репо: `probe-http.html`).
